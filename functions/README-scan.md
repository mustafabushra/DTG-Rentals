# قراءة العقود — نشر الدالة

الدالة `extractContract` تقرأ صورة عقد وتُرجع بياناته منظَّمة. تسكن في مشروعك
على Firebase لا عند مزوّد خارجي، لأن المشروع مهيّأ لـCloud Functions أصلاً.

## لماذا خادم أصلاً؟

العقود صور عربية، ولا يوجد مسار على الجهاز يعطي دقة مقبولة: Tesseract ضعيف مع
العربية، وML Kit لا يدعمها، وVision على iOS فقط بينما تطبيقك ويب أولاً. فالقراءة
تحتاج نموذجاً بصرياً، والنموذج يحتاج مفتاحاً، والمفتاح **لا يجوز** أن يسكن حزمة
الويب — يقرؤه أي أحد يفتح أدوات المطوّر.

## لماذا `onCall` لا `onRequest`؟

الدالة القابلة للنداء تتلقّى الهوية محقَّقة من Firebase في `request.auth`. فلا
تحقق يدوي من الرموز، ولا CORS، ولا رابط علني يستنزفه من يجده. والسرّ يسكن
Secret Manager في مشروعك.

## المطلوب: خطة Blaze

Cloud Functions لا تُنشر على خطة Spark. والترقية إلى Blaze **لا تعني فاتورة**:
فيها طبقة مجانية شهرية سخية (ملايين الاستدعاءات)، وقراءة بضع مئات من العقود
تبقى داخلها. لكنها تطلب بطاقة.

ولو رقّيت، تُحلّ معها قيود تعمل حولها اليوم:

- **Firebase Storage** — المرفقات الآن base64 داخل Firestore بحدّ ميجابايت واحد.
- **عمليات الخادم** — نظام كود الدعوة يعمل client-side، وكتابة سجل التحديثات
  تحتاج سكربتاً محلياً بكلمة مرور المدير الأعلى.
- **الدوال المجدولة الأربع** المكتوبة في `src/index.ts` ولم تُنشر قط.

> **تحذير قبل نشر الدوال المجدولة:** `dailyContractExpiry` و`dailyPaymentOverdue`
> تفعلان ما يفعله التطبيق الآن في العميل. نشرهما معاً يُحدث كتابتين متنافستين على
> نفس المستندات — وهو تماماً صنف السباق الذي سبّب بق «الدفعات المؤكَّدة تعود
> متأخرة». **انشر `extractContract` وحدها** حتى تُراجع الأربع الأخرى:
> ```bash
> firebase deploy --only functions:extractContract
> ```

## النشر

```bash
# ١. الترقية إلى Blaze من لوحة Firebase (مرة واحدة)

# ٢. المفتاح في Secret Manager — لا في ملف ولا في المستودع
firebase functions:secrets:set ANTHROPIC_API_KEY

# ٣. البناء والنشر — الدالة المطلوبة وحدها
cd functions && npm run build && cd ..
firebase deploy --only functions:extractContract
```

لا حاجة لأي متغيّر بيئة في التطبيق: العميل ينادي الدالة بالاسم عبر SDK.

## العقد

```
httpsCallable('extractContract')({ imageBase64, mimeType })
  ⇒ { extraction: { tenantName, startDate, annualValue, confidence, ... } }
```

| الخطأ | المعنى |
|---|---|
| `unauthenticated` | لا جلسة صالحة |
| `resource-exhausted` | تجاوز الحد (30/ساعة لكل مستخدم) أو ازدحام المزوّد |
| `invalid-argument` | صورة مفقودة أو نوع غير مدعوم أو أكبر من 5 ميجابايت |
| `failed-precondition` | النموذج لم يُرجع JSON صالحاً — الصورة غير واضحة |
| `functions/not-found` | الدالة غير منشورة بعد (تعرضه الشاشة كخطوات نشر) |

## الحمايات

**الهوية** — من Firebase، لا تحقق يدوي.

**حدّ المعدل** — 30 قراءة/ساعة لكل **مستخدم** لا لكل IP. *حدّ معروف:* الذاكرة لكل
نسخة دالة وCloud Functions تُشغّل نسخاً متعددة، فالحدّ الفعلي قد يصل إلى
(30 × عدد النسخ). مقبول مع التحقق من الهوية وحدّ الحجم؛ الحدّ الصارم يلزمه مخزن
مشترك وهو تعقيد لا يستحقه الاستخدام الحالي.

**حدّ الحجم** — يُرفض قبل أي استدعاء مدفوع، فالصورة الضخمة لا تكلّفك شيئاً.

## حدود القراءة

النموذج مأمور بنقل القيم **كما هي**: لا يحوّل الهجري إلى ميلادي، ولا الأرقام
العربية، ولا يضرب الإيجار الشهري في 12 — فالضرب استنتاج لا قراءة. التطبيع كله في
`domain/services/ContractExtractionService.ts` حيث هو مختبَر بـ35 اختباراً.

والقراءة **تقترح ولا تكتب**: النتيجة تُعرض في شاشة مراجعة تؤكّدها بنفسك. خطأ قراءة
صفر واحد يضاعف الإيجار عشر مرات، فلا تُحفظ قيمة بلا عين بشرية.

## الاختبارات

```bash
npm test          # من جذر المستودع
```

منطق الدالة مختبَر (التحقق من الطلب، تحليل جواب النموذج المحاط بأسوار أو نثر،
تنقية الحقول الدخيلة، حدّ المعدل). التشفير والشبكة ليست مختبَرة — تُجرَّب عند النشر.
